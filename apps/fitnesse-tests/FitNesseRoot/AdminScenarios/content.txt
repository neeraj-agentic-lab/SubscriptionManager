!2 Prerequisites

Before running these tests:

1. API Server Running: Subscription Engine API must be running on http://localhost:8080
2. Database: !-PostgreSQL-! database must be accessible
3. Test Data: Database should be in clean state (or tests will clean up)
4. Fixtures Built: Run ./gradlew build in fitnesse-tests directory

!2 Running the Tests

!3 Run All Admin Scenarios
Click the Suite button above to run all 11 admin scenario tests.

!3 Run Individual Scenario
Click on any scenario link above, then click the Test button.

!3 Run by Priority
- P0 scenarios: Critical security and onboarding tests
- P1 scenarios: Important operational workflows
- P2 scenarios: Nice-to-have efficiency features

!2 Expected Results

All tests should pass with:
- Green tables indicating successful assertions
- All setup and cleanup completed
- No data leakage between tests
- Audit trails properly recorded

!2 Test Data Management

Each scenario:
- Creates its own test data in setup
- Cleans up all resources in teardown
- Uses unique identifiers to avoid conflicts
- Verifies cleanup completed successfully

!2 Fixtures Used

These scenarios use the following Java fixture:
- !-RestApiFixture-!: REST API client for making HTTP requests to the Subscription Engine API

!2 Troubleshooting

If tests fail:

1. Check API Server: Ensure http://localhost:8080 is accessible
2. Check Database: Verify !-PostgreSQL-! is running
3. Check Logs: Review !-FitNesse-! output and API logs
4. Check Fixtures: Ensure fixtures are built and in classpath
5. Check Test Data: Verify no conflicting data from previous runs

!2 Continuous Integration

These tests can be run in CI/CD:

{{{
# Run FitNesse tests in CI
cd apps/fitnesse-tests
./gradlew clean build
java -jar fitnesse-standalone.jar -c "AdminScenarios?suite&format=xml"
}}}
